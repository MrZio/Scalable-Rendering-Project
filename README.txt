-------------------------------------------------------------------------------
1. OVERVIEW
-------------------------------------------------------------------------------
A tile-based virtual-museum renderer that sustains an interactive frame rate
on high-resolution models (Armadillo, Bunny, Dragon, Happy Buddha) by combining
three techniques:

  - LOD generation     : offline mesh simplification with three selectable
                         methods (simple vertex clustering, QEM, and QEM with
                         normal clustering).
  - Time-critical      : a greedy LOD selector under a fixed per-frame triangle
    rendering            budget (MaxCost = TPS / FPS) with temporal hysteresis.
  - PVS culling        : a Potentially Visible Set precomputed offline and used
                         at runtime to discard occluded geometry.

-------------------------------------------------------------------------------
2. REQUIREMENTS
-------------------------------------------------------------------------------
  - A C++17 compiler. Developed and tested with MinGW g++ on Windows.
  - OpenGL 3.3 or newer.
  - Libraries: GLFW, GLEW (or glad), GLM, Eigen.
  - CMake (to build the engine).
  - (Optional) MeshLab, to clean / convert the input PLY models.

-------------------------------------------------------------------------------
3. PROJECT STRUCTURE
-------------------------------------------------------------------------------
  SRGGE_Base/
    src/ or *.cpp/*.h   Engine sources: Application, Scene, TriangleMesh,
                        TriangleMeshInstance, PLYReader, VectorCamera, main.
    models/
      textured/         ArmadilloJade.ply, bunny.ply, dragon.ply, happy.ply
      room/             Wall.ply, Base.ply
    map.txt             List of model file paths (one per line).
    level.txt           The tile grid that defines the map layout.
    pvs.txt             Precomputed visibility (generated by the PVS tool).
    PVS.cpp             Standalone offline PVS generator (no OpenGL).
    build/              Out-of-source build directory (run the program here).

-------------------------------------------------------------------------------
4. BUILDING THE ENGINE
-------------------------------------------------------------------------------
From the project root (SRGGE_Base):

    mkdir build
    cd build
    cmake ..
    cmake --build .          (or, with MinGW:  mingw32-make)

This produces the executable SRGGE.exe inside the build/ folder.

If you do not use CMake, compile all engine sources together, link against
GLFW + GLEW/glad + OpenGL, and add the GLM and Eigen headers to the include
path.

-------------------------------------------------------------------------------
5. PREPARING THE MODELS  (read this if a model fails to load)
-------------------------------------------------------------------------------
The PLY reader expects BINARY little-endian PLY files that contain only
vertex positions and triangle faces. Models exported directly from Blender
often include extra metadata (vertex colours, normals, UVs, uint index types)
that the reader cannot parse, which results in an empty scene.

Fix: open the model in MeshLab and export it as binary PLY (VCGLIB format),
unticking vertex colours, normals and texture coordinates. Place the cleaned
files under models/textured/ and models/room/ exactly as referenced in map.txt.

-------------------------------------------------------------------------------
6. RUNNING
-------------------------------------------------------------------------------
The program is launched FROM the build/ folder and is passed the map file,
which lives one level up:

    cd build
    ./SRGGE.exe ../map.txt

The working directory matters: the model paths in map.txt and the visibility
file are resolved relative to it, so always run from build/.

-------------------------------------------------------------------------------
7. REGENERATING THE PVS  (only needed if you change level.txt)
-------------------------------------------------------------------------------
The file pvs.txt must match the current level.txt. To regenerate it, compile
and run the standalone tool (it does not use OpenGL):

    g++ -O2 -o pvs PVS.cpp
    ./pvs level.txt pvs.txt

Optionally, print the visibility map from a debug cell (x z):

    ./pvs level.txt pvs.txt 5 6

The engine loads pvs.txt automatically at start-up.

-------------------------------------------------------------------------------
8. CONTROLS
-------------------------------------------------------------------------------
    F1            Toggle navigation mode (capture / release the mouse)
    W A S D       Move    (arrow keys also work)
    Mouse         Look around
    L             Toggle automatic (greedy) LOD vs manual LOD
    Ctrl + / -         Manual LOD level (0 = full detail ... 3 = coarsest)
    C             Toggle LOD colouring  (white=0, blue=1, yellow=2, red=3)
    P             Toggle PVS culling on / off
    M             Cycle clustering mode (simple vertex / QEM / QEM + normal)

                  NOTE: pressing M regenerates all LODs; the window freezes for
                  a few seconds while the Dragon is reprocessed. This is normal.

-------------------------------------------------------------------------------
9. MAP FORMAT
-------------------------------------------------------------------------------
  map.txt    : one model file path per line, in this order:
               Armadillo, Wall, Base, Bunny, Dragon, Happy.

  level.txt  : a grid of digits, one character per cell:
                 1 = wall          0 = floor
                 2 = Armadillo      3 = Bunny
                 4 = Dragon         5 = Happy Buddha
               Each model digit places that model on a pedestal in that cell.

-------------------------------------------------------------------------------
10. IMPLEMENTED FEATURES (see the PDF report for screenshots)
-------------------------------------------------------------------------------
  - Three LOD-generation methods, switchable at runtime (key M):
      * Simple vertex clustering (representative = average of cell positions)
      * QEM standard            (representative = quadric minimum via SVD)
      * QEM + normal clustering (cells split by surface orientation; watertight)
  - Time-critical greedy LOD selection under a fixed triangle budget.
  - Temporal hysteresis (N = 20 frames) to remove LOD popping.
  - Offline conservative PVS (supercover DDA) with runtime culling of models
    and floor tiles.
  - First-person navigation including vertical ascend / descend.
  - LOD colouring debug view.

-------------------------------------------------------------------------------
11. KNOWN LIMITATIONS
-------------------------------------------------------------------------------
At the most aggressive level (LOD 3) the vertex-clustering produces medium,
faceted triangles. This is the expected signature of grid-based clustering and
is only noticeable up close; at the distances where LOD 3 is actually selected
the model is small on screen and the effect is not visible.
